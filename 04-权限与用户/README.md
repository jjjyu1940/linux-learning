# 权限与用户

这一章解决一个最常见的报错：**Permission denied（权限不够）**。先理解为什么，再决定要不要加 `sudo`。

## 一、文件权限是怎么回事

执行 `ls -l` 会看到类似这样的一行：

```
-rwxr-xr--  1 user  staff   2048  9 25 10:00 脚本.sh
↑ 权限     所有者 所属组  大小  修改时间   文件名
```

权限字段拆成四段看：

| 位置 | 含义 |
|---|---|
| 第 1 位 | 文件类型：`-` 普通文件，`d` 目录，`l` 软链接 |
| 第 2–4 位 | 所有者（owner）的权限 |
| 第 5–7 位 | 所属组（group）的权限 |
| 第 8–10 位 | 其他人（others）的权限 |

每位的字母：`r` 可读、`w` 可写、`x` 可执行（目录的 `x` 表示能否进入）。`-` 表示没有这项权限。

## 二、改权限：chmod

```bash
chmod +x 脚本.sh           # 给三类用户都加上可执行权限
chmod u+x 脚本.sh          # 只给所有者加执行权限
chmod 755 脚本.sh          # 用数字表示：rwxr-xr-x
```

常用数字记法：

| 数字 | 权限 | 常见用途 |
|---|---|---|
| `755` | rwxr-xr-x | 脚本、可执行程序 |
| `644` | rw-r--r-- | 普通文本、配置文件 |
| `700` | rwx------ | 只想自己能看的目录或脚本 |

`chmod` 用法：`chmod 目标±权限 文件`。目标为 `u`（所有者）、`g`（组）、`o`（其他人）、`a`（全部）；`+` 加、`-` 减。例如 `chmod o-r 文件` 让其他人不可读。

## 三、sudo：以超级管理员身份执行

```bash
sudo apt update         # 更新软件索引，需要管理员权限
sudo !!                 # 用 sudo 重新执行上一条命令（!! 是上一条命令的占位）
```

- `sudo` 只作用于**它后面的那一条命令**，不是切换到 root
- 第一次用会要求输入**当前用户的密码**，输入时屏幕不显示任何字符，这是正常的
- 连续使用 `sudo` 有一段短时间免密，不必每次都输入

## 四、切换到 root

```bash
su               # 切换到 root，需要 root 密码
sudo -i          # 以 root 身份打开一个新的交互环境
exit             # 退出当前 shell
```

日常操作建议**不要长期停留在 root**，只在需要的那一条命令前加 `sudo`。

## 常见报错

| 报错信息 | 通常是 | 可以怎么做 |
|---|---|---|
| `Permission denied` | 当前用户没有权限 | 先确认要不要改文件属主，再考虑 `sudo`，不要无脑加 |
| `command not found` | 命令不存在，或不在 PATH 里 | `which 命令` 查一下，确认是否装了 |
| `No such file or directory` | 路径写错或文件不存在 | `pwd` + `ls` 先确认 |
| `Operation not permitted` | 权限或文件被占用 | 检查是否正在被使用、属主是否正确 |
